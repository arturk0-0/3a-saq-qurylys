# Изолированная проверка Firestore SDK

Это opt-in QA, **не режим приложения и не проверка живого Firebase**.
Обычные Compose/Hosting/Cloud Run не запускают эмулятор и не импортируют эти файлы.
Production по-прежнему использует онлайн Firebase. Новых зависимостей приложения
и изменений lockfiles нет.

Нужны Linux, Java 21+, Node/npm и установленные backend-зависимости Python 3.12:

```bash
cd backend
uv sync --frozen
cd ..
python3 backend/qa/firestore/run.py
```

Runner использует `backend/.venv/bin/python`, временный Firebase config и
**firebase-tools 15.34.0** через npm exec. Первый запуск скачивает инструменты
и официальный Firestore emulator (в проверенном запуске 1.22.0). Скачивание
требует Интернета; платные Firebase/Gemini-запросы не выполняются. TLS/CA и
настройки proxy сохраняются. Инструменты кэшируются в `/tmp/saq-npm-cache` и
`/tmp/saq-firebase-emulators` (системный temp на другой Linux-машине).

CLI и Java слушают только IPv4 loopback на выбранных свободных портах.
Используется только demo-project; тесты дополнительно требуют явный opt-in,
host `127.0.0.1:port` и случайный проект `demo-saq-it-*` на каждый тест.
Настройки приложения, ADC, cloud project, токены и `.env` не передаются дочерним
процессам. Используются AnonymousCredentials локального SDK; реальный Firebase
Admin JSON не нужен и не должен передаваться. CLI config хранится отдельно в temp.

На каждый одноразовый проект через локальный admin endpoint применяются
**реальные firestore.rules репозитория**. Проверяются реальные SDK-запросы,
транзакции, audit/revisions, пагинация, конкурирующие решения и квота;
обычные REST-клиенты не могут читать или писать документы по этим rules.
Путь нового объявления до PDF выполняет настоящие FastAPI/services/Firestore
и WeasyPrint. Внешние Auth, Storage и Gemini явно заменены тестовыми адаптерами.
Скриншотный тест не измеряет OCR: ответ Gemini задан MockTransport.

Ожидается `19 passed` и exit 0. Каждый запуск начинается с пустого процесса
эмулятора, не импортирует и не экспортирует данные, не делает очистку чужого
проекта. CLI останавливает собственные процессы; runner ограничен 10 минутами
и завершает свою группу процессов при ошибке/прерывании. Логи и JUnit XML
сохраняются в напечатанной папке `saq-firestore-integration-*` системного temp.
В CI есть отдельная job `firestore-integration`; стандартный `pytest` запускает
только обычный `tests/`, без эмулятора. Явный запуск `integration_tests/` без
защитных настроек завершится ошибкой, а не ложным зелёным skip.

Пределы: эмулятор **не проверяет необходимость production composite indexes**,
IAM/публичность bucket, настоящие ID tokens, облачный Storage/PDF, доступность
или качество Gemini, сетевые задержки и поведение production под нагрузкой.
Соответствие деклараций индексов запросам отдельно проверяется unit-тестами;
индексы должны быть опубликованы и готовы в настоящем проекте владельцем.
Запуск этого набора не закрывает ручные release gates из judge-runbook.
Windows-проверка runner не выполнялась.
