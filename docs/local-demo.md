# Локальный запуск для организаторов

Из корня чистой копии репозитория:

```bash
docker compose -f compose.demo.yaml up --build --wait --wait-timeout 180
```

Откройте http://localhost:5173. Вход: `analyst@example.test`, пароль `demo-demo`.
Первая сборка скачивает образы и зависимости; после сборки внешние API не нужны.
Docker Desktop должен работать в режиме Linux containers. Проверялся Linux Docker;
фактическую проверку Windows следует различать с этой проверкой.

## Что именно проверяется

Используются настоящие React UI, FastAPI routes, Pydantic, сервисы доказательств,
скоринг R1–R6, версии/конфликты, история, загрузка изображений и WeasyPrint PDF.
Сохраняются 8 учебных ЖК и 12 объявлений. Есть учебные компании и очередь находок.

Вместо внешних сервисов подключены **явные локальные адаптеры**:

- Данные и загрузки сохраняются в Docker volume `local-demo-data`, не в Firestore.
- Вход — отдельная локальная сессия с непредсказуемым токеном на восемь часов.
  Облачный Firebase не принимает эти токены; обычная авторизация не изменена.
- «Анализ» текста — показ сценария по ключевым словам. В результатах указан
  `local-demo-rules-not-gemini`, исходный фрагмент и предупреждение. Эти правила
  не используются как полноценная классификация реальной рекламы.
- Скриншоты валидируются и сохраняются, но не распознаются; дрон-анализ возвращает
  `uncertain` по всем пунктам. Можно проверить интерфейс и ручное рассмотрение.
- Сбор источников возвращает вымышленную публикацию. Он не ищет настоящие посты.
- Homeportal/ADATA/Ashyq не запрашиваются. Существуют учебные страницы организаций;
  обновление из внешнего справочника вернёт явную ошибку недоступности.
- Изображения карты из внешней сети блокируются локальным CSP. Условные здания
  и переходы доступны на пустой подложке; обычный сайт использует OpenStreetMap.

Во всех экранах сохраняется заметная плашка локального режима. Оригиналы загруженных
файлов требуют сессию. Пользовательские данные и файлы сохраняются при `down/up`;
сессии после перезапуска API нужно получить заново.

## Сценарий проверки

1. Войти и сравнить контрольные A/B/C: 35/YELLOW, 70/RED, 10/GREEN.
2. Открыть «Реклама → Все материалы», добавить вымышленное объявление с
   предложением депозита. Оно автоматически поступает в очередь учебного анализа.
3. Открыть материал: оригиналы, цитаты, гипотезы, ЖК и документы находятся рядом.
   Приоритет меняется предварительно, подтверждённый риск остаётся прежним.
4. Выбрать явные решения по гипотезам, добавить комментарий и сохранить одну
   проверку. Сервер согласованно обновляет доказательства и подтверждённые факторы.
5. Создать сигнал, передать на проверку, вернуть/подтвердить и скачать PDF.
6. Загрузить скриншот и дрон-фото. Файлы сохраняются и доступны после входа;
   локальные ответы не являются распознаванием изображения.
7. Открыть организации, рекламный след и карту. Учебные контакты в seed не
   относятся к реальным владельцам. Внешняя подложка карты локально заблокирована.

Подробный пошаговый маршрут: [проверка за 5 минут](judge-runbook.md).

Автоматическая проверка требует только стандартную библиотеку Python 3.12+:

```bash
python scripts/check-local-demo.py
```

Она создаёт отдельный учебный объект и проверяет полный цикл, не снимая решений
со старых записей. Дополнительные созданные объекты сохраняются после проверки.

## Остановка, сброс и нативный запуск

```bash
docker compose -f compose.demo.yaml down
# Только если хотите удалить все локальные учебные данные и файлы:
docker compose -f compose.demo.yaml down -v
```

Для разработки без Docker сначала установите Python 3.12/uv, Node 24 и системные
зависимости PDF по [инструкции разработчика](development.md#зависимости). В первом терминале из `backend/`:

```bash
uv sync --frozen
uv run --frozen python -m local_demo
```

Во втором, из `frontend/`:

```bash
npm ci
npm run demo
```

В нативном режиме порты 8000/5173; API по умолчанию привязан к 127.0.0.1.
Docker demo публикует только localhost:5173, а API доступен через proxy.
Локальные записи находятся
в `backend/.local-demo-data/`. Нельзя запускать несколько API workers с одной
папкой JSON: этот адаптер рассчитан на один локальный процесс.

## Изоляция от настоящего сайта

`compose.demo.yaml` — самостоятельный файл, а не override рабочего Compose.
Backend использует отдельный Dockerfile и entry point `local_demo`; production
Dockerfile копирует только `app/`, без локального пакета. В Cloud Run локальная
factory дополнительно отказывается запускаться. Cloud Run/Hosting не получают
демосессии, демоданные или правило обхода Firebase.

Frontend использует отдельную Vite-конфигурацию с alias локальной сессии. Обычные
`npm run build` и `build:hosting` этих alias и плашки не содержат. В Compose runtime
нет env_file и монтирования ключей; `.env` не передаётся в контейнеры. Backend
подключён только к внутренней сети без egress. Frontend дополнительно имеет bridge
для опубликованного loopback-порта 5173; внешние browser API/изображения ограничены
CSP. Не публикуйте демоконтейнеры в Интернет.

Корпоративный HTTPS-прокси может требовать доверенный CA при **сборке** образов.
Оба Dockerfile поддерживают BuildKit secret `custom_ca`. Он нужен лишь в такой
среде и не заменяет проверку TLS. Не включайте `strict-ssl=false` или insecure mode.


## Если не запускается

| Ситуация | Что проверить |
| --- | --- |
| Docker не отвечает | Docker Desktop/Engine запущен, используется Linux containers. |
| Compose не находит файл | Команда выполняется из корня с `compose.demo.yaml`. |
| Первый запуск занимает время | Идёт загрузка зависимостей; посмотрите логи, затем повторите ту же команду. |
| Порт 5173 занят | Остановите предыдущую копию или другое приложение на этом порту. |
| Открылся экран настройки Firebase | Использован основной Compose; для запуска без ключей нужен отдельный `compose.demo.yaml`. |
| Данные пропали после перезапуска | Обычная остановка — `down`; `down -v` удаляет локальный volume. |

```bash
docker compose -f compose.demo.yaml ps
docker compose -f compose.demo.yaml logs --tail 50
```

Ожидаются два `healthy` сервиса. Проверить API через frontend proxy можно по
http://localhost:5173/api/local-demo/info: ответ содержит `mode: local-demo`.
