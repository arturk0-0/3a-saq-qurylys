## Что реализовано

- Организации идентифицируются по БИН (`bin-{12 цифр}`), роли задаются отдельно
  для каждого проекта. Один БИН с двумя ролями имеет одну страницу.
- Названия/БИН/сайт и связи берутся из публичной карточки Homeportal. Дата
  регистрации — из открытого справочника ADATA, только при совпадении БИН.
  ADATA — вторичный коммерческий справочник, не государственная выписка.
- Каждый факт содержит publisher, точный URL, retrievedAt, effectiveDate (если
  известна), SHA-256 ответа и статус source_reported. Различающиеся значения
  сохраняются вместе. Даты получения не выдаются за даты обновления источника.
- Страницы организаций и блок двух участников ЖК показывают источники рядом
  со значениями, даты, неизвестные сведения, частичный охват портфеля.
- При переименовании БИН не меняется; название/роль/источник фиксируются в
  снимке конкретного ЖК. Новые сигналы/PDF используют эти же снимки; старые
  сигналы не переписываются. DEMO-маркировка остаётся у вымышленных данных.
- Поиск → просмотр конкретной карточки → явное сохранение участников.
  Реальный ЖК создаётся только отдельным явным действием, если сервер уже
  разрешает реальные записи (`DEMO_ONLY=false`). DEMO-карточки не дополняются
  реальными компаниями; существующие ЖК не перезаписываются.
- Адрес и координаты только из locationData конкретного объекта Homeportal.
  Нулевые/нечисловые/вне города точки отбрасываются, геокодирования и подмены
  стройки офисом продаж нет. Сохранена форма coordinates {latitude,longitude}|null.
- Наличие гарантии/планового срока не означает сдачу. Счётчик учитывает только
  карточки с непустыми реквизитами акта и его регистрации, корректными датами;
  дубли акта/даты/адреса объединяются. Это число найденных карточек, не полный
  подсчёт физических ЖК или всего портфеля. Пока карточек нет — null.
- Auth на всех endpoints, ежедневная общая квота публичных операций, ограничения
  времени/объёма ответа, optimistic locking и атомарность записи с аудитом.
  Сохранённые сведения служат кэшем: открытие страниц не обращается к источникам.
  Ошибка обновления сохраняет предыдущие значения и даты.

## Источники: фактическое бесплатное чтение

Проверялись общедоступные HTTPS-страницы без авторизации и без обхода CAPTCHA.
Реальные ответы/контакты/досье в репозиторий и тестовые fixtures не помещались.

1. `api.homeportal.kz/api/v1/getobjects` и `objects-detail/{id}`: карточки 1487
   и 1505 возвращают двух участников с БИН, адрес и точку объекта. У 1487 точка
   (0,0) отвергнута; у 1505 точка внутри Усть-Каменогорска. Каталог строящихся
   объектов подтверждает этап этих карточек; реквизитов зарегистрированного
   акта ввода в них не обнаружено. Точность до участка отдельно не подтверждена.
   Ссылка пользователю: `https://homeportal.kz/ru/projects/{id}`.
2. Публичная HTML-страница `https://pk.adata.kz/company/{BIN}`: SSR содержит
   совпадающий БИН и явное reg_date формата DD-MM-YYYY (возраст). Парсер берёт
   только дату, а не руководителей, контакты, учредителей или рейтинг.
   Канонический путь установлен по самой публичной странице; redirect не разрешён.
3. Старый открытый BNS `stat.gov.kz/api/juridical/bin/` вернул 404. Работающего
   официального источника даты регистрации пока не установлено. eGov/E-License
   не объявлены подключёнными; login/CAPTCHA не обходились.

Источники могут меняться. Юридический адрес/статус остаются неизвестными до
достоверного отдельного источника. Утверждения компаний не становятся проверкой
законности; R1–R6, auth/rules и подтверждённые факторы не менялись.
