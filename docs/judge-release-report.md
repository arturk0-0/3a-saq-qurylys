## Подготовлено

- Совместная версия: сверка оснований, страницы компаний, карта города, дрон.
- Отдельный `compose.demo.yaml` для чистого запуска без `.env` и облачных ключей.
- Локальные сессии, вымышленные данные и файлы в отдельном volume. Серверный
  скоринг, evidence review, сигналы и PDF используют обычные сервисы приложения.
- Явные учебные анализ/сбор без сетевых запросов к провайдерам; баннер во всех экранах.
- Production Dockerfile не копирует `local_demo/`; cloud auth/rules не ослаблены.
- Новый README, `docs/local-demo.md`, стандартная библиотека Python для smoke-проверки,
  отдельный CI job с перезапуском контейнеров и повторной проверкой.
- `deploy/publish-reviewed-release.sh`: публикация проверенного checkout в Cloud Shell;
  обычная Hosting-сборка, индексы, API image с сохранением env/secrets/identity/limits,
  health/anonymous 401, Hosting и обновление image существующего worker без запуска.

## Публикация после проверок

Из **чистой авторизованной** копии окончательного release/main checkout в Cloud Shell:

```bash
bash deploy/publish-reviewed-release.sh "$(git rev-parse HEAD)"
```

Передаётся именно полный SHA проверенного checkout, а не переменная старой сборки.
Скрипт не публикует локальную Vite-конфигурацию, не загружает seed и не меняет роли.
В настоящем проекте остаётся выбранная модель/секрет Gemini, настройки SearchAPI и
сервисный аккаунт. Новые индексы должны закончить построение до проверки запросов.

Живая приёмка после публикации: вход существующим аналитиком, старые объявления и
сигналы, новые разделы организаций/карты/дрона, загрузка приватного фото, история и
PDF. Новый AI-запрос не является частью автоматического deploy smoke. Не выдавать
локальные ответы за облачную проверку или новое качество Gemini.

## Ограничения

Windows Docker Desktop и реальная новая облачная версия ещё не проверены в этой
сессии. Новые роли компаний не означают полного реестра подрядчиков; неизвестные
сведения не заполнены. Дрон не анализирует видео/полёт и не подтверждает соблюдение
всех строительных норм. Реальный основной проект по состоянию проверки GitHub API
приватный; доступ организаторам требует отдельной публикации или приглашения.
