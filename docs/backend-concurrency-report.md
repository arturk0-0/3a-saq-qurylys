## Этап 1 — ошибки SDK

**Воспроизведено до исправления: 2 failed, 2 passed** в новом наборе
`tests/test_transaction_failures.py`. Использован настоящий Firestore SDK и его
transactional decorator с заменёнными RPC: доступа к облаку нет.

- После трёх `Aborted` на commit SDK выбрасывает `ValueError` с явной причиной
  `Aborted`. Прежний адаптер пропускал его как внутреннюю ошибку 500.
  Теперь это существующий `409 CONFLICT`: пользователь обновляет данные перед
  явным повтором. Прочие `ValueError` по-прежнему не маскируются.
- Истечение SDK retry deadline даёт `google.api_core.exceptions.RetryError`,
  который не является `GoogleAPICallError`. Теперь Firestore read/query/transaction
  и Storage upload/download возвращают существующий безопасный
  `503 INTEGRATION_UNAVAILABLE`, без текста исключения и его причины.
- Дополнительных автоматических повторов операций не добавлено. При неизвестном
  исходе commit приложение не запускает callback повторно. SDK-повторы `Aborted`
  остаются ограничены прежними тремя попытками.

Целевые проверки SDK/query/Storage: 21 passed. Ruff check всего backend успешен.

## Этап 2 — загрузки и конкурентные действия

**Гонка загрузки воспроизведена до исправления:** два потока одновременно
загрузили изображение до проверки версии в транзакции. Один получил 409,
в объявлении осталась одна ссылка, но в Storage — два объекта.

Теперь отдельный внутренний тип конфликта обозначает отказ callback по версии
до любых записей. Только в этом достоверном случае удаляется уникальный объект
проигравшего запроса. Обычный Conflict, ошибка Storage, неизвестный исход commit
и потерянное подтверждение commit не приводят к удалению. Ошибка удаления не
подменяет исходный 409 и журналируется без текста исключения. Автоматическая
очистка прочих orphan objects не добавлялась.

Проверено отдельными тестами:

- Две конкурентные загрузки: один объект, одна attachment-ссылка, одно событие
  аудита и одна новая версия объявления.
- Неизвестный исход транзакции как до, так и после фактического commit:
  файл сохраняется; после commit остаётся доступным по доказательству.
- Ошибка удаления orphan: исходный конфликт сохраняется, приватные детали
  исключения не попадают в журнал; дальнейшая очистка остаётся администратору.
- Четыре дубликата AI-запроса во время первого вызова: 409, один вызов провайдера,
  одна гипотеза, одна запись аудита, однократное списание квоты. Повтор после
  успеха возвращает сохранённый результат.
- 12 одновременных запросов от трёх пользователей при global=3/user=2:
  три успеха, девять `AI_DAILY_LIMIT`, оба лимита соблюдены, факторы не меняются.
- Успешное сохранение AI с потерянным ответом: повтор не вызывает Gemini,
  не удваивает доказательства и не перезаписывает success ошибкой.
- Два решения по одному фактору: один победитель, один 409, единственное событие
  с правильным актором и изменением оценки 35→10; алгоритм R1–R6 не менялся.
- Одновременные confirm/return сигнала: один победитель, одна новая версия,
  старый снимок/ревизия неизменны, reviewer и audit согласованы.
- Четыре параллельных seed import: один импорт, 37 документов, один marker и
  один audit с сохранённым первоначальным актором.

Потоковые тесты используют существующие MemoryStore/FakeFiles/MockTransport и
барьеры/события с timeout. Они проверяют прикладные транзакционные границы;
поведение настоящего SDK проверено отдельно с заменёнными RPC. Это не
нагрузочное измерение и не тест производительности живого Firestore.

## Проверка и публикация владельцем

Команды локальных backend-проверок из корня репозитория:

```bash
cd backend
uv sync --frozen
uv run --frozen ruff check .
uv run --frozen ruff format --check .
uv run --frozen pytest -q
```

После независимого review и зелёного CI **последнего коммита**, из корня
проверенного checkout с этими backend-изменениями, при желании публикации:

```bash
SAQ_IMAGE="europe-west1-docker.pkg.dev/saq-qurylys/saq-qurylys/api:concurrency-$(date -u +%Y%m%d-%H%M%S)"
gcloud builds submit . --project=saq-qurylys \
  --config=deploy/cloudbuild.yaml --substitutions="_IMAGE=$SAQ_IMAGE"
```

Только после `SUCCESS` сборки, в той же сессии:

```bash
gcloud run services update saq-qurylys-api --project=saq-qurylys \
  --region=europe-west1 --image="$SAQ_IMAGE"
```

Обновляется только образ: действующие env, секреты, сервисный аккаунт и
выбранная владельцем модель сохраняются. Hosting эта ветка не меняет.
Для публикации frontend друга нужен отдельно проверенный checkout его работы;
проверка временного сочетания веток не означает, что они уже объединены.

## Оставшаяся ручная приёмка и пределы

Все локальные adapters обозначены как тестовые; результаты не подтверждают
живые Firestore contention, Storage/IAM, облачный PDF и реальный Gemini.
Длительность SDK retries в живой сети не измерялась; общий дедлайн всех RPC
внутри Firestore transaction не менялся. Это классификация исчерпанных retries,
а не гарантия предельного wall-clock времени.

Владелец проверяет прежнюю облачную матрицу из judge-runbook после публикации:
вход, обычный новый анализ, проверка источника/фактора, сигнал, историю и PDF.
Проверку гонок/квот проводить в отдельном DEMO-проекте, без платных провайдеров;
не запускать потоковый тест против живого сайта.
При неизвестном commit исходе сначала обновлять карточку/историю. Для AI
использовать тот же requestId при проверке сохранённого результата: новый ID
означает новый анализ и расход квоты. Не обещается автоматическое восстановление
записи `running`, если процесс был прерван: сохранена консервативная защита от
повторной оплаты, без фоновых workers и новых API.

`main`, production, правила доступа и файлы параллельного Кодекса не изменены.
