# Сценарий демонстрации

Нужны настроенные Firebase, Gemini, роль analyst/admin и импорт DEMO.
Предварительно проверьте docs/firebase-setup.md и docs/ai-methodology.md.
Короткий показ, резерв при сбое Gemini и ручная приёмка после публикации:
[judge-runbook.md](judge-runbook.md). Опубликованный сайт и локальный запуск
различаются: README содержит оба пути. Исправления в PR не означают deployment.
Текст выступления: [pitch.md](pitch.md); подготовка и резерв:
[demo-checklist.md](demo-checklist.md). Клики ниже соответствуют реализации
PR #6/#7 в `main`; фактическую опубликованную версию проверяет владелец.
Загрузка seed create-only не сбрасывает решения аналитика: для повторяемого показа
используйте отдельный учебный проект или заранее подготовленную неизменённую копию.

## Новое объявление до PDF

1. Откройте учебный объект с R3 confirmed, R2 unknown и текущим серверным баллом 10.
   В исходном seed это Горная мозаика (demo-complex-04), но shared DEMO мог быть
   уже изменён. Проверьте состояние; create-only seed не сбрасывает решения.
2. Объявления → Добавить. Введите новую синтетическую публикацию, например
   «DEMO: строящийся ЖК Горная мозаика. Для бронирования внесите депозит
   135 000 тенге». Укажите учебную ссылку https://demo.invalid/new-review,
   вымышленный аккаунт и дату. Сохраните оригинальный текст.
3. «Скриншоты и AI-анализ» → шаг 1 «Выберите материал» → в поле
   «Источник анализа» выбрать «Текст объявления». В шаге 2 сверить строку
   «Будет проанализирован» → «Анализировать выбранный источник».
   Это должен быть настоящий запрос
   Gemini, не запись старого ответа. При отсутствии ключа показывается ошибка.
4. В шаге 3 проверьте точную цитату, неопределённость и условия платежа.
   Модель гипотезы — в «Сведения об AI-анализе». Для сведений о конкретном
   запуске сначала раскройте «История запусков анализа (…)», затем строку запуска.
   Gemini может не выделить R2: тогда честно покажите результат и проверьте
   источник вручную, не выдавая ручной вывод за AI.
5. «Рассмотреть гипотезу» → «Решение по гипотезе»: «Принять к проверке» →
   обоснование → «Сохранить решение». Балл остаётся 10.
6. «К доказательству» → «Проверить источник» → явно отметьте предложение
   платежа, внесите обоснование, подтвердите источник. Балл всё ещё 10.
7. «Решение по фактору R2» → «Подтвердить фактор» → выбрать этот проверенный
   источник → обоснование → сохранить. Ожидается 35, YELLOW.
8. «Создать сигнал» → заголовок/причина → создать черновик.
   Передайте на проверку → верните с причиной → передайте повторно → отдельно
   подтвердите. История должна содержать каждое решение и его автора/время.
9. «Скачать PDF»: проверьте статус, 35 баллов, цитату/источник, reviewer,
   даты и метку DEMO. Подтверждение сигнала не меняет балл.

Для скриншота: шаг 1 → «Добавить скриншот» → выбрать синтетический
JPEG/PNG/WebP до 6 MiB → «Загрузить». После успешной загрузки
файл выбирается автоматически; нажать «Открыть скриншот», сверить имя файла,
предпросмотр и поле
«Источник анализа» перед шагом 2. Только выбранный материал отправляется
на анализ; загрузка сама по себе не запускает Gemini.
Сверьте OCR глазами с оригиналом. Нечёткий/безобидный
источник не должен подаваться как подтверждённое нарушение.

## Рекламный след — отдельная ручная проверка

Подготовьте два новых вымышленных объявления одного DEMO-объекта с разными
аккаунтами и ссылками `https://demo.invalid/trace/one` и
`https://demo.invalid/trace/two`. Тексты:

> DEMO — вымышленное объявление. Контакт +7 (000) 000-00-01.

> DEMO — другой вымышленный аккаунт. WhatsApp https://wa.me/70000000001

Номера учебные, звонить/писать по ним не нужно. Откройте первое объявление →
«Рекламный след». Сравните точные цитаты «Это объявление» / «Другое объявление»;
«К связанному объявлению» открывает конкретную сохранённую публикацию.
Вернитесь назад → раскройте панель → «Рассмотреть совпадение» → выбрать
«Подтвердить совпадение» либо «Отклонить совпадение» → обоснование →
«Сохранить решение о совпадении». Перезагрузите страницу, снова откройте панель
и сверьте сохранённый статус. Для второго решения используйте другую ещё
не рассмотренную пару: UI не отменяет уже подтверждённый/отклонённый снимок.

Это совпадение признаков исходных **текстов**, не установление общего владельца
или незаконности. Скриншоты и закрытые аккаунты здесь не сравниваются, Gemini
не вызывается, R1–R6 не меняются. При пустом результате или сообщении об
ограничении выборки нельзя утверждать, что связей нет. Подробности:
[advertising-trace.md](advertising-trace.md).

## Отрицательные проверки

- Без входа защищённые API возвращают 401; без роли — 403.
- Р1 нельзя подтвердить только потому, что записи нет в DEMO.
- Гипотеза без проверки не увеличивает балл.
- Измените фактор после передачи сигнала на проверку: подтверждение старого
  снимка блокируется; нужно вернуть и передать повторно.
- При недоступном Gemini существующие карточки/источники остаются доступны.
- Не выдавайте тестовые adapters или записанное видео за работающий live AI.

Автоматический прогон этой цепочки: backend/tests/test_vertical_flow.py.
Он проверяет код приложения с явно тестовым внешним transport. Для приёмки
нужно отдельно записать дату, GEMINI_MODEL и результаты настоящего облачного прогона.

Локальный Chromium runner с настоящими API/services и явно тестовыми внешними
адаптерами: [frontend/qa/release](../frontend/qa/release/README.md). Его успешный
exit не подтверждает облачную историю/индексы, Firebase token/rules/IAM, качество
Gemini или Windows. Эти результаты записываются отдельно.
## Сравнение названий из AI (AI-05)

После завершённого анализа раскройте «История запусков анализа (…)», затем
строку нужного запуска под кнопкой анализа.
Если AI извлёк названия, нажмите «Найти ЖК по названиям». Сравните название,
город, альтернативное имя и оригинальное объявление. При нескольких совпадениях
нет автоматического выбора: нажмите «Выбрать для сравнения», затем откройте
выбранную карточку. Привязка объявления, доказательства и риск не изменяются.
Отсутствие совпадений не подтверждает отсутствие правового основания/R1.
Для проверки неоднозначности в тестовом наборе можно задать одинаковый alias
двум вымышленным ЖК; не используйте реальные названия застройщиков для обвинений.
