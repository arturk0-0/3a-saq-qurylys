# Сценарий демонстрации

Нужны настроенные Firebase, Gemini, роль analyst/admin и импорт DEMO.
Предварительно проверьте docs/firebase-setup.md и docs/ai-methodology.md.
Загрузка seed create-only не сбрасывает решения аналитика: для повторяемого показа
используйте отдельный учебный проект или заранее подготовленную неизменённую копию.

## Контрольные объекты

| Сценарий | ЖК | Подтверждено | Ожидание |
| --- | --- | --- | --- |
| A | Янтарный берег, demo-complex-01 | R2 + R3, основание неизвестно | 35, YELLOW |
| B | Кедровый квартал, demo-complex-02 | R1 + R2 + R3 | 70, RED |
| C | Солнечный склон, demo-complex-03 | Применимая гарантия, R3 | 10, GREEN |

Обзор → карточка → документы/доказательства → источники под R1–R6.
Все названия, БИНы, адреса и выводы seed вымышлены и обозначены DEMO.
Высокий приоритет не является правовым заключением.

## Новое объявление до PDF

1. Откройте Горную мозаику (demo-complex-04), исходный балл 10.
2. Объявления → Добавить. Введите новую синтетическую публикацию, например
   «DEMO: строящийся ЖК Горная мозаика. Для бронирования внесите депозит
   135 000 тенге». Укажите учебную ссылку https://demo.invalid/new-review,
   вымышленный аккаунт и дату. Сохраните оригинальный текст.
3. «Скриншоты и AI-анализ» → анализ текста. Это должен быть настоящий запрос
   Gemini, не запись старого ответа. При отсутствии ключа показывается ошибка.
4. Проверьте точную цитату, неопределённость, модель и условия платежа.
   Gemini может не выделить R2: тогда честно покажите результат и проверьте
   источник вручную, не выдавая ручной вывод за AI.
5. Примите гипотезу к проверке. Балл остаётся 10.
6. «К доказательству» → «Проверить источник» → явно отметьте предложение
   платежа, внесите обоснование, подтвердите источник. Балл всё ещё 10.
7. R2 → «Пересмотреть» → «Подтвердить фактор» → выбрать этот проверенный
   источник → обоснование → сохранить. Ожидается 35, YELLOW.
8. «Создать сигнал» → заголовок/причина → создать черновик.
   Передайте на проверку; отдельно подтвердите или верните с причиной.
9. «Скачать PDF»: проверьте статус, 35 баллов, цитату/источник, reviewer,
   даты и метку DEMO. Подтверждение сигнала не меняет балл.

Для скриншота загрузите новый синтетический JPEG/PNG/WebP, выберите его в
источнике анализа. Сверьте OCR глазами с оригиналом. Нечёткий/безобидный
источник не должен подаваться как подтверждённое нарушение.

## Отрицательные проверки

- Без входа защищённые API возвращают 401; без роли — 403.
- Р1 нельзя подтвердить только потому, что записи нет в DEMO.
- Гипотеза без проверки не увеличивает балл.
- Измените фактор после передачи сигнала на проверку: подтверждение старого
  снимка блокируется; нужно вернуть и передать повторно.
- При недоступном Gemini существующие карточки/источники остаются доступны.
- Не выдавайте тестовые adapters или записанное видео за работающий live AI.

Автоматический прогон этой цепочки: backend/tests/test_vertical_flow.py.
Он проверяет код приложения с явно тестовым внешним transport. Для приёмки
нужно отдельно записать дату, GEMINI_MODEL и результаты настоящего облачного прогона.
## Сравнение названий из AI (AI-05)

После завершённого анализа раскройте строку запуска под кнопкой анализа.
Если AI извлёк названия, нажмите «Найти ЖК по названиям». Сравните название,
город, альтернативное имя и оригинальное объявление. При нескольких совпадениях
нет автоматического выбора: нажмите «Выбрать для сравнения», затем откройте
выбранную карточку. Привязка объявления, доказательства и риск не изменяются.
Отсутствие совпадений не подтверждает отсутствие правового основания/R1.
Для проверки неоднозначности в тестовом наборе можно задать одинаковый alias
двум вымышленным ЖК; не используйте реальные названия застройщиков для обвинений.
