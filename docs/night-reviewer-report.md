## Воспроизведения перед исправлением frontend

- **AUTH-01:** войти с принятым токеном → API следующего раздела отвечает 401.
  На базе навигация и рабочая оболочка остаются; меняется только ошибка запроса.
  Если `getIdToken()` отклонён с `auth/user-token-expired`, интерфейс также остаётся
  открытым и показывает исходный текст SDK exception. Два новых regression-теста
  воспроизвели дефект (2 failed), контрольный offline-тест прошёл.
- **NAV-01:** в реестре задать поиск/город/приоритет → открыть карточку → browser
  Back. На базе фильтры сбрасывались, так же при reload. Regression-тест упал
  на пустом поле поиска после возврата. Теперь применённые параметры и курсор
  хранятся в URL, browser Back/Forward/reload восстанавливают выборку.
- **SIGNAL-01:** открыть создание сигнала, заполнить заголовок/основание → другой
  аналитик меняет версию ЖК → создать. Ответ 409 сохранял поля, но повтор всегда
  посылал прежнюю версию; полный reload терял ввод. Regression-тест сначала упал
  из-за отсутствия безопасного обновления. Теперь есть «Обновить данные ЖК»:
  GET новой версии, сохранение обоих полей, явная повторная проверка и отправка.

## Этап 3 — сочетания конфликтов и regression-тесты

- **REVIEW-01 (три редактора):** открыть проверку источника / фактора / основания,
  ввести решение, другим запросом изменить соответствующую версию, сохранить.
  409 показывался, но редакторы не умели обновить версию без потери ввода.
  Три regression-теста сначала упали из-за отсутствия read-only refresh. Добавлен
  общий `useReviewRecord`: форма остаётся смонтированной, свежая версия/серверные
  сведения видимы, текст/checkbox сохранены, повторная отправка только явно.
  При ошибке GET кнопка обновления остаётся доступной, запись заблокирована,
  черновик сохранён. Источник, уже связанный с подтверждённым фактором, по-прежнему
  нельзя менять без пересмотра фактора; backend остаётся решающим.
- **AI-REVIEW-01:** набрать обоснование/выбрать отклонение гипотезы → 409 →
  «Обновить результаты». На базе textarea сбрасывалась при загрузке списка.
  Тест воспроизвёл пустое поле. Теперь поля управляются состоянием панели.
  Если другой аналитик уже рассмотрел гипотезу, несохранённый текст виден отдельно,
  повторное решение не отправляется. Backend не менялся.
- **PDF-01:** вернуть HTML с ошибочно указанным `application/pdf`. Старый MIME
  guard разрешал скачивание под `.pdf`; новый тест воспроизвёл отсутствие ошибки
  и создание download URL. Теперь до Blob URL проверяются MIME и первые пять
  байтов `%PDF-`; HTML/пустой/не-PDF ответ не скачивается. Это проверка сигнатуры,
  не полноценный валидатор всех PDF-объектов.

Расширенный Chromium с реальными локальными конкурентными API-записями прошёл:
15 групп / 497 browser requests, 0 page errors / внешних запросов. Дополнительно
пройдены source deep link + reload + фокус, конфликты AI/source/factor/basis при

цитату 135 000, `qa-local-analyst` и заголовок в настоящем локальном PDF.
После дополнительного PDF guard проводится финальный прогон ниже.

После PDF guard: **61 frontend tests passed**, 15 test files; typecheck и build
успешны. Есть предупреждение Vite о main chunk ~501 kB (gzip ~154 kB), без
подавления порога и без несвязанного рефакторинга. Chromium с обоими HTML MIME

Новых подтверждённых backend-дефектов в этом проходе не найдено. Общий код
`CONFLICT` покрывает несколько причин: например, открыть source review, другим
запросом подтвердить связанный фактор, затем сохранить прежний source review —
backend корректно отклоняет действие, но не отдаёт отдельный typed code для
блокировки источника. UI даёт фиксированную подсказку проверить факторы. Код/
контракт не менялись. Причина прежней облачной ошибки истории здесь не установлена.
