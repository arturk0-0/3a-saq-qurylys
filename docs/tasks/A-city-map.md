## Задачи по порядку

- [ ] MAP-01: переиспользовать существующие Leaflet/OpenStreetMap и защищённый API. Новый вторичный сворачиваемый блок «Карта города» в `/complexes` (реестр ЖК), по умолчанию закрыт, ограниченная высота около 320–400 px. Таблица и фильтры остаются основным содержимым. Не переделывать карту приоритета на обзоре.
- [ ] MAP-02: одинаковые объёмные шаблоны многоэтажек, привязанные к координатам; CSS 3D / объёмная геометрия SVG в Leaflet divIcon, без новой картографической платформы. Это условные модели, не реальные контуры/этажность. Панорамирование, zoom, выбор здания мышью/клавиатурой. Никакой визуализации готовности или раскраски этажей/корпусов по риску.
- [ ] MAP-03: по выбору — название, адрес, ссылка на существующую карточку ЖК. Совпадающие координаты группировать с выбором объекта, не сдвигать здания на выдуманные позиции. Данные — из существующего API; город по умолчанию Усть-Каменогорск, показывать известные `stage=under_construction` с координатами. Не подписывать неизвестный статус как подтверждённое строительство. Указать число показанных объектов и предел покрытия (текущая выборка/страница либо ограниченный пагинированный набор). Не объявлять первую страницу всеми ЖК города.
- [ ] MAP-04: отсутствующие/некорректные координаты не подменять офисом продаж/центром города; показать понятное сообщение. Учебные координаты обозначать условными; не выдавать их за адреса реальных строек. Без координат — объект остаётся в списке. Сбор и проверку реальных координат выполняет B, карта работает до этого на существующих записях.
- [ ] MAP-05: lazy loading только при открытии, отсутствие скачков страницы/перехвата scroll, ResizeObserver cleanup, обработка ошибок тайлов, attribution OSM и обычное умеренное использование тайлов без массовой предзагрузки. Mobile 375/320, desktop 1366, keyboard/focus, reduced motion. Ошибка карты не блокирует реестр.
- [ ] MAP-06: содержательные Vitest tests геометрии/группировки/безопасных popup/навигации и lifecycle, typecheck/build, доступный локальный browser QA с явно тестовыми адаптерами. Никакой подмены реального runtime фикстурами. Итоговый handoff с командами, результатами, скриншотами и ограничениями покрытия.

## Границы и отсутствие ручных действий

A владеет `frontend/src/features/city-map/**` (новая папка), минимальным подключением в `frontend/src/features/complexes/ComplexList.tsx`, отдельными map-тестами и `docs/map-handoff.md`. Не переписывать общий CSS: стили scoped внутри city-map. Существующий ComplexMap можно читать и переиспользовать его подходы, но не переписывать общий обзор. Не менять ComplexDetail.tsx, App/routes, shared lib/types.ts, backend, seed, rules, общие план/WORK_LOG — ими занимается B. Не редактировать общий browser runner одновременно с B: для новой проверки использовать отдельный map QA файл/инструкцию.

Дополнительные frontend файлы — только если необходимы для подключения карты, перечислить в handoff. Никакой смены Leaflet на MapLibre/Mapbox/Three.js, внешних 3D SDK или новых платных провайдеров. Если настоящая объёмная геометрия не помещается в Leaflet, сохранить работающий прототип и описать ограничение; не заменять требование обычной плоской меткой молча.

**Не нужны** Firebase/Google Cloud login, API keys, кабинеты, ручные действия владельца, реальные AI/SearchAPI запросы или deploy. Зависимости и локальную проверку устанавливает Codex по инструкциям репозитория. Нет инструментов/доступа — сначала диагностировать и продолжать независимую часть; не просить друга настраивать облако. Вымышленные тестовые записи не публиковать как реальные адреса.
