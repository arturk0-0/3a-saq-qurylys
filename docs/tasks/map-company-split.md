## Согласованный результат

**Карта:** небольшой дополнительный сворачиваемый блок в реестре ЖК, по умолчанию
закрытый. Усть-Каменогорск, Leaflet/OSM, одинаковые условные объёмные здания на
известных координатах строящихся ЖК (`stage=under_construction`). Название, адрес и переход к ЖК по выбору здания.
Без процентов готовности, шкалы этажей и зависимости вида здания от риска.
Объёмные CSS/SVG-модели на карте не являются реальной архитектурой или цифровым
двойником города; новая 3D-картографическая платформа не нужна. Учебные точки
условные, неизвестные координаты не придумываются. Покрытие выборки указано явно.

**Организации:** в карточке ЖК отдельно юридический застройщик и уполномоченная
компания. Каждая организация имеет страницу, идентификация по БИН. При одном
БИН и двух ролях — одна страница с двумя ролями. Рядом с каждым значением —
компактная ссылка на конкретную страницу источника, где есть этот факт/дата.
Дата регистрации, дата сведений и дата получения различаются. Полнота портфеля
не предполагается: «Найдено завершённых объектов» с перечнем, а не выдуманный
общий счётчик. Неизвестные данные не заменяются нулями.

## Порядок

1. A начинает карту независимо; B проверяет источники и текущую модель компаний.
2. B реализует provenance/связи/API и собственный frontend страниц организаций.
3. Оба сохраняют маленькие проверенные коммиты и отдельные PR/handoff.
4. B проводит независимый review и объединяет только после CI; проверяет общий
   сценарий «карта → ЖК → компания → источник» и мобильную версию.
5. Публикация API/Hosting выполняется отдельно из одного проверенного SHA.

R1–R6, auth/rules, веса/цвета риска не меняются. Платные Gemini/SearchAPI запросы
и обходы login/CAPTCHA для этих задач не требуются. Неполный источник не является
отрицательным юридическим фактом. PR #19 и прежние работающие потоки сохраняются.
