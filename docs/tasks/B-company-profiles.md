## Задачи по порядку

- [ ] ORG-01: исследовать доступные публичные источники. Начать с Homeportal и документов по объектам, затем официальных государственных открытых страниц/наборов с идентификацией по БИН. E-License/eGov и другие порталы использовать только в реально доступной части без обхода login/CAPTCHA. Сайт компании — дополнение с явной атрибуцией «по данным компании». Зафиксировать фактически доступные поля, даты и ограничения; не обещать дату регистрации, пока источник не найден.
- [ ] ORG-02: спроектировать обратно совместимые контракты организации и связей с ЖК. Разделять бренд, юридического застройщика, уполномоченную компанию и роль в конкретном объекте/очереди. БИН — основной идентификатор, одинаковое название не основание для объединения. Один БИН с двумя ролями — одна страница, две роли. Старые developerId/Developer и seed должны продолжать работать; authorizedCompany nullable, без выдуманного заполнения.
- [ ] ORG-03: каждому факту хранить значение, название источника, точный sourceUrl страницы с этим значением, дату получения, дату сведений/действия (если известна), статус/неопределённость. Дата получения не заменяет дату регистрации/сдачи/обновления. При конфликте источников сохранять расхождения и не выбирать красивое значение молча. В UI возле значения компактный кликабельный источник; дата проверки в подсказке/раскрытии, неизвестные поля явно отсутствуют. Если исторический permalink недоступен, не заявлять, что живая ссылка воспроизводит страницу на прошлую дату.
- [ ] ORG-04: основные сведения — юридическое название, БИН, дата регистрации, статус, юридический адрес, сайт, связанные ЖК и роли — только при достаточном источнике. Портфель завершённых объектов строить по подтверждаемому перечню и определениям: ЖК/корпус/этап считать раздельно, исключить дубли/переименования. Не выводить сдачу из date_end, прошедшего срока или наличия гарантии. При неполном охвате писать «Найдено завершённых объектов в источнике», а не «Всего сдано»; отсутствие данных — null, не 0. Ссылки на перечень/объекты обязательны. Неподтверждённые заявления компании отделять от официальных данных.
- [ ] ORG-05: реализовать ограниченные серверные адаптеры/кэш/квоты, хранение и защищённые endpoints, без arbitrary URL fetch/SSRF, секретов/сырого provider body/персональных контактов в логах. Источники недоступны — сохранённый снимок со временем и понятной ошибкой. Обновление по явному действию с пределом запросов; никакого неограниченного обхода сайтов, фонового массового импорта или платного AI/SearchAPI.
- [ ] ORG-06: добавить в карточку ЖК блок «Участники проекта»: юридический застройщик и уполномоченная компания, БИН, роль, источник связи, переходы на страницы организаций. Страница организации: основные сведения и источники около полей, портфель/методика подсчёта/даты. Сохранить Auth, прямые ссылки, loading/error/empty, читаемость, mobile, скрытие UID. B владеет всем необходимым frontend компаний, не ждёт A.
- [ ] GEO-01: для реально найденных ЖК сохранять адрес и координаты только с источником/статусом точности. Не импортировать реальные организации в вымышленные DEMO-карточки, не превращать адрес офиса продаж в координаты стройки. Новые реальные карточки — отдельные записи без выдуманных факторов/готовности. При неоднозначности оставить координаты неизвестными. Существующий coordinates {latitude,longitude}|null сохраняется для карты A, дополнительное provenance — обратно совместимо. Ни карта, ни эти страницы не меняют R1–R6.
- [ ] ORG-07: unit/API auth/валидация/ошибки/неполные данные/совпадения по БИН/дубли/даты, native SDK по затронутым запросам/атомарности при необходимости, frontend tests + typecheck/build, локальный browser workflow с явными test adapters. Реальное бесплатное чтение источников отделить от моков и облачной приёмки.
- [ ] ORG-08: отчёт docs/company-profiles-report.md, контракты/инструкции/общий план и WORK_LOG, небольшие проверенные коммиты, push, PR, независимое review и зелёный CI. После интеграции A проверить совместную версию. Облако не публиковать автоматически в этой задаче.

## Границы и самостоятельность

B владеет backend, моделями/API/документами, общими types, App/routes, ComplexDetail.tsx и новым company frontend. **Не менять параллельно** `frontend/src/features/city-map/**`, `ComplexList.tsx`, `docs/map-handoff.md` и общий frontend CSS, который использует A. Для компаний отдельные scoped стили. Смена карты/массовая переработка UI не требуется.

Не расходовать SearchAPI/Gemini квоту и не требовать аккаунтов/секретов от друга. Если закрытый источник недоступен, продолжать на проверенных открытых источниках, фиксировать неизвестное вместо выдумки. Не добавлять реальных обвинений, не менять auth/rules/скоринг или автоматически подтверждать legal basis. Полнота источника, статус строительства и юридическая применимость — разные понятия.
