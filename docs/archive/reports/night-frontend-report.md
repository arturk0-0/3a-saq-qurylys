## Этап 1 — понятные и безопасные ошибки

Добавлены русские сообщения новых backend-кодов Gemini, Firestore indexes и PDF.
Вместо provider message показывается только фиксированное описание и прошедший

properties. Поля API и правила риска не менялись.

Проверка текущего рабочего дерева: TypeScript и 44 frontend-теста прошли, включая

Baseline до изменений: 25 passed. Реальный Firebase/Gemini в этих тестах не вызван.

## Этап 2 — отдельные решения и доступные редакторы

- Добавлена короткая схема AI → источник → фактор → сигнал; AI явно необязателен,
  баллы приходят с сервера после отдельного решения по фактору.
- Для evidence используются подписи «Источник проверен/не проверен», а AI origin
  показан отдельно. Исходный sourceReference сохранён в раскрываемых реквизитах:
  историческое unverified не выдаётся за текущий статус. Подтверждённый источник
  предлагает отдельное решение в панели R1–R6; locked evidence остаётся locked.
- Редактор фактора получает фокус и прокрутку к форме; отмена возвращает фокус.
  Предыдущие evidenceIds подтверждённого фактора сохраняются при открытии.
  Пустое подтверждение предлагает выбрать доказательство, без вычисления score.
- «Повторить» теперь type=button: раньше внутри формы оно могло одновременно
  отправить решение. Добавлен regression test на отсутствие лишней записи.
- Подсказки FormField связаны через aria-describedby, отдельно от label.
  Skip link и переход между разделами фокусируют main; вкладки сохраняют свою
  клавиатурную навигацию. Широкие таблицы имеют именованную scroll region/tab stop.
- Узкая навигация показывает четыре ссылки сеткой; длинные строки/кнопки
  переносятся. На desktop риск-панель ограничена высотой окна и прокручивается;
  на узком экране обычный поток. Print не включает редакторы и подсказку этапов.

Chromium с явным локальным AuthContext/API fixture и заблокированными внешними
запросами: 1366×768, 375×812, 320×700 — без горизонтального выхода страницы;
фокус/cancel и прокрутка таблицы ArrowRight проверены. После первого визуального
прогона прокрутка heading изменена на start, чтобы первый control не оставался
под нижней границей экрана. Финальный расширенный прогон ещё выполняется.

Текущий рабочий набор: 47 tests / TypeScript passed; production build прошёл
до последней небольшой правки skip link, финальная сборка будет повторена.

## Этап 3 — сигнал, обновление и скачивание

Комментарий решения теперь управляется состоянием страницы: сохраняется после
ошибки POST, явного обновления данных и скачивания PDF, очищается после успешного
решения или перехода к другому сигналу. Обновление данных не отправляет решение.
При недоступной/неактуальной карточке подтверждение сигнала недоступно, но возврат
остаётся отдельным действием; есть retry проверки актуальности. Backend-проверка
версий остаётся решающей, payload не менялся.

PDF скачивается приватным API-запросом через временно присоединённый download link,
затем link удаляется, Blob URL освобождается. Тест проверяет также cleanup и
сохранение комментария; Blob в frontend-тесте заведомо тестовый, не настоящий PDF.
История сигнала имеет явные loading/error/empty состояния.

47 frontend-тестов и финальная production-сборка прошли. Полный Chromium-прогон:
1366×768, 1024×768, 768×1024, 375×812, 320×700. Нет выхода страницы за экран;
первое поле редактора видно после открытия, отмена возвращает фокус. Проверены
ошибки source/factor save с сохранением текста/checkbox, keyboard table scroll,
signal comment после failed save/refresh/mock PDF download, отсутствие лишнего
POST, skip link и route focus. Необработанных page errors нет; внешние запросы
блокировались, попыток внешних запросов в прогоне не было.

## Проверить и опубликовать после review

```bash
cd frontend
npm ci
npm test
npm run build
```

Для Hosting нужен именно `build:hosting` с собственным `.env.production.local`
**в корне репозитория**, как в docs/cloud-deployment.md. Не публиковать обычную
CI-сборку без production origin. В Cloud Shell из корня **актуальной этой ветки**
можно скопировать существующую browser config первой публикации (если папка та же):

```bash
if [ ! -e .env.production.local ]; then
  cp ~/saq-deploy/3a-saq-qurylys-feat-DEPLOY-01-hosting-cloud-run/.env.production.local .env.production.local
fi
cd frontend
npm ci
npm run build:hosting
```

Только после успешной сборки, из frontend:

```bash
cd ..
npx firebase-tools@15.34.0 deploy --only hosting --project saq-qurylys
```

Скопированный файл содержит только public VITE browser config/API origin;
не добавлять Gemini/Admin credentials и не коммитить .env. Если конфигурация уже
есть в новой папке, сохранить её и проверить значения, не перезаписывать вслепую.
Backend обновляется отдельно по docs/cloud-deployment.md, раздел 6; эта ветка уже
включает ac11efc, но сама backend после него не меняет. Main не изменялся.

После публикации владельцу проверить реальный вход, новые сообщения ошибок,

Chromium проверен локально; другие браузеры и полный аудит WCAG не выполнялись.
