## A-01: воспроизведённые дефекты и исправления

Регрессионные тесты сначала воспроизвели пять сбоев на прежней реализации;
затем исправлены причины. Шестой тест проверяет возврат клавиатурного фокуса.

| Воспроизведение на исходном UI | Проблема | Результат исправления |
| --- | --- | --- |
| Открыть анализ → выбрать скриншот → рассмотреть гипотезу, изменить решение/заметку → скрыть/открыть анализ | Терялись выбранный материал и черновик | Панель монтируется по первому открытию, затем скрывается без уничтожения состояния; нет дополнительных чтений при повторном открытии |
| Рекламный след → рассмотреть пару, заполнить обоснование/отклонение → скрыть/открыть панель | Терялось введённое решение | Черновик сохраняется при сворачивании панели той же карточки |
| В локальном transport заменить ответ `GET /evidence/{id}/file` на HTTP 200 `text/html` → открыть скриншот | HTML предлагался как оригинал, показано сломанное изображение | До Blob URL проверяется MIME JPEG/PNG/WebP; понятная ошибка, нет ссылки скачивания HTML, доступен повтор |
| Вернуть повреждённые байты с `image/png` → открыть → вернуть исправный файл | После ошибки декодирования не было восстановления | `img.onError` освобождает URL, показывает ошибку и кнопку повторного открытия; исправный PNG реально декодируется |
| Начать открытие файла → уйти со страницы до ответа | Поздний ответ создавал ненужный Blob URL | После unmount URL не создаётся; использованные URL освобождаются |
| Рассмотреть совпадение → «Отмена» → Enter | Фокус терялся при удалении формы | Фокус возвращается на конкретную кнопку; `aria-expanded`/`aria-controls` описывают раскрытие |

Сохранение черновика относится к сворачиванию панели внутри смонтированной
карточки. Это не постоянное сохранение после reload, выхода или смены маршрута.
Решения не отправляются автоматически. Проверки HTML/декодирования — искусственные
локальные ответы; дефект живого backend этим не утверждается.

Изменены `AdvertisementsPage`, `TracePanel`, `EvidenceFile`; добавлены шесть
Vitest-проверок и browser-регрессии. Browser также проверяет новый upload →
автоматический выбор → отправку именно `screenshotId` и актуальной версии
в анализ; результат MockTransport не подтверждает реальное качество OCR.

## A-02: измерение и восстановление загрузки

Одинаковый toolchain/lockfile, production Vite build, размеры в десятичных kB:

| Сборка | Начальный JS | gzip по Vite | Предупреждение >500 kB |
| --- | ---: | ---: | --- |
| main / ed38f00 | 512,89 | 156,05 | Есть |
| Только A-01 | 513,76 | 156,24 | Есть |
| A-02 | 430,42 | 135,98 | Нет |
| A-01 + A-02 | 430,42 | 135,98 | Нет |

`React.lazy` загружает страницы ЖК, объявлений и сигналов после входа по
потребности. Manifest подтверждает: статическое замыкание начального JS — один
entry-файл 430 417 bytes, страницы не спрятаны в его синхронных imports.
Уменьшение относительно main — 82,47 kB / 16,1%; gzip — 20,07 kB / 12,9%.
Это размер стартового JS, не измерение времени загрузки или суммарного трафика
всех страниц. Leaflet по-прежнему отдельный динамический chunk 149,90 kB.
CSS разделён на initial 35,55 kB и каталог/карту 15,61 kB.
Лимит предупреждения, зависимости и инфраструктура не менялись.

Навигация остаётся вне route error boundary. При ожидании импорта виден status;
при отказе — понятная ошибка и reload текущего URL. Переход на другую страницу
сбрасывает boundary. Повтор после отказа через reload нужен, поскольку React.lazy
кеширует отклонённый import; пользователь явно выбирает действие, API-записи
не повторяются. Reload не сохраняет незаписанный ввод.

Browser в свежем контексте доказал отсутствие запроса защищённого route-модуля
до входа, задержку импорта, отказ/навигацию/фокус/reload, отсутствие POST в этой
проверке. Отдельная проверка обычной production-сборки без Firebase показала
«Подключите рабочую среду», без запросов route/Leaflet chunks и page errors.
