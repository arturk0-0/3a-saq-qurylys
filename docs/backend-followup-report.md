## Завершённые локальные изменения

- `26db9b5`: безопасная диагностика `AI_INVALID_RESPONSE`: внешний JSON,
  блокировка/кандидаты, незавершённая генерация, структура частей, размер,
  JSON извлечения, схема, цитата вне оригинала. Только фиксированные причины,
  серверный UUID, allowlist finish reason и режим text/image. Общий request ID
  работает и для HTTP/сетевых отказов. Проверена изоляция параллельных запросов.
  Ключи, исходники, ответы/размышления модели и ошибки Pydantic не логируются.
- `cf60fe3`: исправлен воспроизведённый конфликт пометок PDF. Исторический
  `AI hypothesis; …; unverified` сохраняется дословно и объясняется отдельно
  от последующей проверки аналитиком. Решение по сигналу показано отдельно
  от проверки источников; статусы и факторы имеют русские подписи.
- `d4cb214`: ширина колонок PDF задана через colgroup; таблица помещается
  в страницу, статус «Подтверждено» не разрывается в проверенном примере.
  Финальная визуальная проверка также расширила колонку «Баллы» до 10%.
- `6de9147`: устранено неверное ожидание в SDK concurrency test. При исчерпании
  ограниченных повторов обе конкурирующие транзакции могут вернуть 409.
  Тест сначала доказывает отсутствие бизнес-записи и аудита у обоих отказов,
  затем явно повторяет один запрос с прежней версией. Сохранены требования
  ровно одного изменения версии/score и одной записи аудита с верным актором.
  Runtime-повторы не добавлены; сценарий устаревшего конкурентного решения
  по-прежнему обязан завершаться конфликтом.

API-коды/JSON-схемы, модель/prompt, бюджет генерации, R1–R6, переходы сигнала,
auth/rules и приватность файлов не изменены. База данных и старые снимки
не переписываются. Невалидный ответ не чинится и не повторяется автоматически.

## Оставшиеся шаги и ограничения

1. Review зависимых PR: #6 → #7 → эта ветка. После слияния базы переключить
   base следующего PR на main и проверить CI на актуальном SHA. Не сливать
   старые #1–4 повторно: они уже включены ранее через #5. Обновление ролей
   команды — отдельный [PR #10](https://github.com/arturk0-0/3a-saq-qurylys/pull/10).
2. B-03 завершён в части диагностики. Причина исторического сбоя
   `d73b89fd-…` **не установлена**: старый лог не содержит новых полей.
   Если следующий обычный анализ после публикации завершится ошибкой,
   сопоставить UUID с безопасным логом по `docs/cloud-deployment.md`.
   Не запускать платный вызов только ради диагностики.
3. Реальные измерения RU/KZ/бесплатного бронирования/размытого изображения
   остаются отдельным шагом в согласованном бюджете. Metadata GET 200 не
   подтверждает generation. Локальные моки не измеряют качество Gemini.
4. B-04 завершён в части подтверждённого PDF-дефекта и локальных регрессий.
   Облачные IAM/доступ к объектам после выхода и чистую установку на втором
   устройстве проверять в опубликованной версии; эмулятор этого не доказывает.
   Финальная проверка секретов выполняется на release SHA перед публичностью.

## Последующая публикация

Публиковать только после review, слияния и зелёного CI из **нового checkout
одобренного SHA**. Старый Cloud Shell каталог `saq-release-effb87f` не содержит
этих правок. PR #7 также требует обновления Hosting; собственные изменения
этой ветки затрагивают только API/PDF. Полная инструкция и сборка Hosting:
[cloud-deployment.md](cloud-deployment.md).

Из корня нового checkout с согласованным `deploy/` и действующим Cloud Shell
доступом владельца; заменить `APPROVED_SHA` на полный проверенный SHA:

```bash
SAQ_RELEASE_SHA=APPROVED_SHA
SAQ_RELEASE_IMAGE="europe-west1-docker.pkg.dev/saq-qurylys/saq-qurylys/api:release-${SAQ_RELEASE_SHA}"
gcloud builds submit backend --project=saq-qurylys --tag="$SAQ_RELEASE_IMAGE"
gcloud run services update saq-qurylys-api --project=saq-qurylys --region=europe-west1 --image="$SAQ_RELEASE_IMAGE"
```

Это платные cloud-операции; здесь они не выполнялись. Update сохраняет прежние
env/secrets/service account и модель: не подставлять пример env поверх текущей
рабочей конфигурации. После обновления проверить health, закрытый endpoint без
token, PDF с прежним снимком и подтверждённым источником. Обновлённые причины
ошибок доступны только у новой revision; автоматической смены модели нет.
