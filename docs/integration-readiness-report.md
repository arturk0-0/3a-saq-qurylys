   и все четыре ветки A; не сливать старые PR #1–4 повторно. При включении
   интеграции #14 становится поглощённым, а отдельные A-ветки уже включены.

   собрать API/Hosting из одного checkout. [Основное обновление](cloud-deployment.md#6-обновление-существующего-сайта-из-проверенного-main)
   и разделы 7–8 `cloud-deployment.md` описывают MON и SearchAPI. Если заголовок
   раздела изменился, ориентироваться на номера 6/7/8, а не старый ZIP.

   `SEARCHAPI_ENABLED=true`, расписание сначала `false`, daily limit 2,
   reserve 20. Значения ключей не переносить через чат/Git. Настройки Codex
   не переносятся в Cloud Run автоматически.
4. Опубликовать новые индексы, дождаться READY, выполнить короткую ручную приёмку
   MON без авто-AI. Затем отдельно включить Job/Scheduler и проверить реальный
   запуск. Не создавать несколько источников «для теста» с лишним расходом поиска.
5. Выбрать реальные Telegram-каналы: встроенного списка нет, неизвестные
   каналы глобально не ищутся. Проверять доступность/тематику перед подключением.
6. Реальные ЖК и доказательства вести отдельно от DEMO. Автоматическая загрузка/

   ссылки. Их нельзя объявлять завершёнными по успеху текстового поиска.
