# Gemini: извлечение гипотез

Реальный серверный REST adapter использует Google Gemini `generateContent`.
Модель выбирается только через `GEMINI_MODEL`, ключ — `GEMINI_API_KEY` (backend).
Нет встроенного ответа, запасной фиктивной модели или запроса из браузера.
Нужна модель, поддерживающая изображения и `responseJsonSchema` в Gemini API.

Prompt version: `advertising-extraction-v1`, полный текст в
`backend/app/services/gemini.py`. Температура 0, максимум 4096 output tokens.
Извлекаются предложения R2/R3, точные цитаты, названия ЖК, условия платежей,
неопределённость, необязательная самооценка confidence. Confidence не калибрована
и не является вероятностью нарушения. R1 запрещён схемой ответа.

Текст объявления передаётся как данные. Промпт запрещает выполнять содержащиеся
в нём инструкции. Модель не получает инструментов, доступ к БД, внешним ссылкам,
команды изменения статусов или серверные credentials.
Pydantic отклоняет посторонние поля, неподдержанные факторы и некорректные значения.
Для текстового анализа каждая цитата должна быть точной подстрокой оригинала.
OCR изображения проверить этим способом невозможно: его текст всегда гипотеза,
аналитик открывает сохранённый оригинал и проверяет самостоятельно.

Объявление привязывает к ЖК человек при создании. В завершённом анализе раскройте
детали запуска → «Найти ЖК по названиям». Сервер сравнивает названия из AI-результата
с названием и явно заданными командой `aliases` внутреннего реестра. Сопоставление
приводит регистр/Unicode/пунктуацию и префиксы DEMO/ЖК к общему виду; частичное
совпадение требует минимум двух общих слов. Это эвристика, а не вероятность.

При нескольких совпадениях UI явно сообщает неоднозначность и требует выбрать
объект для сравнения. Даже единственный кандидат не выбирается автоматически.
Кнопка открывает карточку для сравнения; она не сохраняет новую привязку и не
подтверждает связь, источник, R1–R6 или сигнал. Модель не может добавлять алиасы.
Если кандидат отличается от текущей привязки, аналитик получает предупреждение.
Исправление существующей привязки и перенос доказательств отдельным workflow
пока не реализованы; они не должны происходить скрыто.

Поиск ограничен 500 записями текущего DEMO-scope и 10 кандидатами на название;
достижение ограничений явно отображается. Отсутствие совпадений не устанавливает
отсутствие правового основания и никогда не даёт R1. Алиасы — справочные названия,
а не проверенная связь застройщиков или общий владелец рекламных аккаунтов.

## Процесс

1. Объявления → добавить новый текст и источник → «Скриншоты и AI-анализ».
2. При необходимости загрузить JPEG/PNG/WebP до 6 МиБ и 20 мегапикселей.
   Сервер проверяет формат/размер, хранит оригинал приватно и SHA-256.
3. Выбрать текст или скриншот → «Анализировать выбранный источник».
4. Проверить цитату и неопределённость; принять гипотезу к проверке либо отклонить.
5. В ЖК → Доказательства явно проверить источник и факты.
6. Отдельно в R1–R6 подтвердить фактор с проверенным источником и обоснованием.

Ни анализ, ни принятие гипотезы автоматически не меняют факторы или балл.
Каждая гипотеза хранит model, promptVersion, inputSha256, runId, evidenceId.
Отклонённая гипотеза сохраняется для аудита; её источник не становится ложным
или подтверждённым автоматически. Если позднее он используется, это новое явное
решение аналитика по первоисточнику.

## Ограничения и эксплуатация

- По умолчанию 20 запусков на пользователя/сутки UTC и 100 на проект/сутки UTC.
  Счётчики Firestore атомарны; неудачные попытки тоже учитываются. Один запуск
  может сделать два вызова провайдера (повтор только после 502/503/504).
- Таймаут чтения 30 секунд, подключения 5; не повторяем неопределённый timeout
  автоматически. UUID запроса исключает повтор анализа после успешной записи.
- После обрыва процесса run может остаться running: сначала обновить результаты.
  Администратор проверяет состояние перед новой попыткой; фонового worker нет.
- Ошибки/квота не превращаются в «гипотез не найдено».
- Объект Storage и Firestore не имеют общей транзакции. Неопределённый сбой
  сохранения может оставить приватный объект без ссылки; автоматическое удаление
  небезопасно при неопределённом commit. Администратор очищает только проверенные
  несвязанные объекты. Storage IAM не должен разрешать публичное чтение.

## Фактическая валидация

### Воспроизводимый малый прогон

В репозитории есть **входы**, а не готовые ответы модели:
`backend/app/cli/ai_cases.json`. Семь вымышленных случаев: русский/казахский платёж,
бесплатное бронирование на двух языках, недоверенная инструкция внутри объявления,
сгенерированный чёткий скриншот и его размытый вариант. Для скриншотов нужен DejaVu Sans
или Arial; Docker уже содержит DejaVu Sans. В image-запрос не передаётся скрытая текстовая
копия изображения. Набор опубликован и мал: его результат не измеряет точность на новых данных.

Из `backend/` посмотреть случаи без сетевых запросов:

```bash
uv run --frozen python -m app.cli.evaluate
```

После настройки реального ключа/доступной модели начать с одного случая:

```bash
uv run --frozen python -m app.cli.evaluate --run --limit 1
uv run --frozen python -m app.cli.evaluate --run
```

Для Docker выполняйте ту же Python-команду через
`docker compose -f compose.yaml -f compose.firebase.yaml exec backend .venv/bin/python -m app.cli.evaluate --run`.
Генерация **платная**, до семи случаев на запуск; каждый случай может сделать один
повтор после временной ошибки провайдера. CLI предназначен для разработчика и не
использует дневные Firestore-счётчики приложения. Он останавливается после первой
ошибки сервиса, не подставляет вымышленные ответы и не меняет Firestore/скоринг.

По умолчанию JSON/PNG сохраняются в `backend/artifacts/ai-evaluation/` при запуске
из `backend/` (`--output` меняет путь). В Docker это `/app/artifacts/ai-evaluation/`;
после успешного запуска скопируйте перед пересозданием контейнера:

```bash
docker compose cp backend:/app/artifacts ./
```

Отчёт содержит дату, модель, prompt version, hash набора/входа, время, точные ответы,
ожидаемые/полученные R2/R3 и статусы passed/failed/error/manual_review. Размытый скриншот
всегда требует ручного заключения. Код 2 — нет корректной конфигурации (отчёт не создан),
1 — ошибки/расхождения; 0 допускает manual_review и не закрывает live release gate.
Автоматическая проверка цитат на сгенерированных картинках допускает отличия только
в пробелах; произвольные пользовательские скриншоты по-прежнему проверяет аналитик.
Повторный запуск переписывает отчёт: сохраняйте разные `--output` для сравнения моделей.
Результаты игнорируются Git до ручной проверки; после неё внесите итог и ограничения
в этот документ. Для демонстрации дополнительно нужен новый, ранее не публиковавшийся ввод.

Unit/API tests используют явно тестовый HTTP transport: русский/казахский ввод,
пустой результат, выдуманная цитата, R1, forged status, 429, повреждённый файл,
квоты, повторный requestId, независимость решений и отсутствие смены score.
Это проверка контракта и защит, **не измерение качества модели**.
По сообщению владельца, 15 октября облачный анализ нового объявления моделью
`gemini-3.5-flash-lite` завершился успешно; после ручной проверки R2 оценка
изменилась с 10 на 35. Это не измерение точности на корпусе и не проверка
всех облачных сценариев. Предыдущая `gemini-2.5-flash-lite` отвечала metadata GET
200, но generation 404; доступность generation нельзя выводить из metadata.
Модель в коде автоматически не переключается. Локальные QA/emulator-прогоны
используют Gemini MockTransport, поэтому не добавляют live-измерений качества.
Перед демонстрацией записать модель/дату, новые RU/KZ тексты, бесплатную бронь,
нечёткий скриншот и фактические ответы в отдельный протокол; не подменять live
тест заранее заготовленным результатом.

## Диагностика отклонённого ответа

`AI_INVALID_RESPONSE` остаётся публичным кодом 502: гипотезы не сохраняются,
оригинал объявления доступен для повторной проверки. Серверная строка
`Gemini request failed:` содержит серверный `request_id`, этап и причину
из фиксированного списка. Переданный клиентом `X-Request-ID` не используется.
Контекст запроса передаётся в синхронный обработчик и сбрасывается после ответа.

| Причина в безопасном логе | Что отклонено |
| --- | --- |
| `envelope_json`, `envelope_shape` | Внешний ответ не JSON или имеет неверную структуру |
| `prompt_blocked`, `no_candidates` | Блокировка запроса или отсутствие кандидатов |
| `candidate_shape`, `parts_shape`, `no_text` | Неверная структура кандидата/частей или нет видимого текста |
| `incomplete_generation` | `finishReason` не равен `STOP`, включая обрыв по лимиту |
| `output_too_large` | Видимый текст длиннее 40 000 символов |
| `extraction_json`, `extraction_schema` | Извлечённый текст не JSON или не проходит схему Pydantic |
| `unanchored_quote` | Цитата текстового анализа отсутствует в оригинале |

`finish_reason` тоже ограничен списком известных значений; произвольное значение
провайдера заменяется на `unknown`, отсутствующее — на `missing`. `input` сообщает
только `text`/`image`. Части с `thought=true` не используются как результат.
Проверка цитаты по исходному тексту сохранена; OCR изображения требует ручной
сверки и не считается автоматически подтверждённым доказательством.

Логи не содержат ключ, заголовки, исходное объявление, байты картинки, тело ответа,
размышления модели или содержимое ошибок Pydantic. Клиент получает прежнее
фиксированное сообщение и код обращения, без внутренних причин. Модель, prompt,
JSON-схема, бюджет генерации и правила повторов не изменены: невалидный ответ
не повторяется автоматически. Причину старого сбоя нельзя восстановить по новым
логам; для диагностики нужен новый запрос после публикации этой версии.
