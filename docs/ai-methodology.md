# Gemini: извлечение гипотез

Реальный серверный REST adapter использует Google Gemini `generateContent`.
Модель выбирается только через `GEMINI_MODEL`, ключ — `GEMINI_API_KEY` (backend).
Нет встроенного ответа, запасной фиктивной модели или запроса из браузера.
Нужна модель, поддерживающая изображения и `responseJsonSchema` в Gemini API.

Prompt version: `advertising-extraction-v1`, полный текст в
`backend/app/services/gemini.py`. Температура 0, максимум 4096 output tokens.
Извлекаются предложения R2/R3, точные цитаты, названия ЖК, условия платежей,
неопределённость, необязательная самооценка confidence. Confidence не калибрована
и не является вероятностью нарушения. R1 запрещён схемой ответа.

Текст объявления передаётся как данные. Промпт запрещает выполнять содержащиеся
в нём инструкции. Модель не получает инструментов, доступ к БД, внешним ссылкам,
команды изменения статусов или серверные credentials.
Pydantic отклоняет посторонние поля, неподдержанные факторы и некорректные значения.
Для текстового анализа каждая цитата должна быть точной подстрокой оригинала.
OCR изображения проверить этим способом невозможно: его текст всегда гипотеза,
аналитик открывает сохранённый оригинал и проверяет самостоятельно.

Объявление привязывает к ЖК человек при создании. Названия, найденные Gemini,
показываются для сравнения; автоматической смены привязки нет. Автоматический
поиск кандидатов по алиасам пока не реализован.

## Процесс

1. Объявления → добавить новый текст и источник → «Скриншоты и AI-анализ».
2. При необходимости загрузить JPEG/PNG/WebP до 6 МиБ и 20 мегапикселей.
   Сервер проверяет формат/размер, хранит оригинал приватно и SHA-256.
3. Выбрать текст или скриншот → «Анализировать выбранный источник».
4. Проверить цитату и неопределённость; принять гипотезу к проверке либо отклонить.
5. В ЖК → Доказательства явно проверить источник и факты.
6. Отдельно в R1–R6 подтвердить фактор с проверенным источником и обоснованием.

Ни анализ, ни принятие гипотезы автоматически не меняют факторы или балл.
Каждая гипотеза хранит model, promptVersion, inputSha256, runId, evidenceId.
Отклонённая гипотеза сохраняется для аудита; её источник не становится ложным
или подтверждённым автоматически. Если позднее он используется, это новое явное
решение аналитика по первоисточнику.

## Ограничения и эксплуатация

- По умолчанию 20 запусков на пользователя/сутки UTC и 100 на проект/сутки UTC.
  Счётчики Firestore атомарны; неудачные попытки тоже учитываются. Один запуск
  может сделать два вызова провайдера (повтор только после 502/503/504).
- Таймаут чтения 30 секунд, подключения 5; не повторяем неопределённый timeout
  автоматически. UUID запроса исключает повтор анализа после успешной записи.
- После обрыва процесса run может остаться running: сначала обновить результаты.
  Администратор проверяет состояние перед новой попыткой; фонового worker нет.
- Ошибки/квота не превращаются в «гипотез не найдено».
- Объект Storage и Firestore не имеют общей транзакции. Неопределённый сбой
  сохранения может оставить приватный объект без ссылки; автоматическое удаление
  небезопасно при неопределённом commit. Администратор очищает только проверенные
  несвязанные объекты. Storage IAM не должен разрешать публичное чтение.

## Фактическая валидация

Unit/API tests используют явно тестовый HTTP transport: русский/казахский ввод,
пустой результат, выдуманная цитата, R1, forged status, 429, повреждённый файл,
квоты, повторный requestId, независимость решений и отсутствие смены score.
Это проверка контракта и защит, **не измерение качества модели**.
Live Gemini/Firebase не проверены: отсутствуют настройки и ключи приложения.
Перед демонстрацией записать модель/дату, новые RU/KZ тексты, бесплатную бронь,
нечёткий скриншот и фактические ответы в отдельный протокол; не подменять live
тест заранее заготовленным результатом.
